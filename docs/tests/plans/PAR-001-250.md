# Plan de tests · Espace parent, `REC-PAR-001` à `REC-PAR-250`

Statut : plan à implémenter (aucun test écrit). Source : `apps/web/e2e/CAHIER-DE-RECETTE.md`, partie 4 « Espace parent », écrans « Shell » à « Paramètres parent » (début). Stratégie générale : `docs/tests/PLAN-DE-TESTS.md` ; dispositif : `docs/tests/FIXTURES-FAUSSE-API.md`.

## 1. En-tête

Tranche : 250 scénarios (`REC-PAR-001` à `REC-PAR-250`). Les numéros `REC-PAR-165` à `207` sont intercalés dans la section « Historique de commande » et « Achat direct de kit » (déjà convertis) ; les numéros `441` à `481` de ces mêmes sections appartiennent à une autre tranche.

| Stratégie | Nombre | Scénarios |
| --- | --- | --- |
| Déjà automatisé (`auto`) | 42 | 165 à 178, 180 à 207 (dont 177 et 185 « partiel ») |
| A · fonctionnel sur fixtures | 201 | tout le reste, sauf lignes ci-dessous |
| B · bout en bout vraie stack | 3 | 088, 093, 103 |
| C · unitaire (pytest) | 2 | 104, 121 |
| D · hors e2e / manuel | 1 | 179 |
| E · à spécifier | 1 | 057 |
| **Total** | **250** | |

Effort estimé (S moins d'une demi-journée, M une journée, L plus) pour les 201 scénarios A : fausse API et fixtures de la famille parent L (environ 4 jours), 13 fichiers de test (3 L, 8 M, 2 S, soit environ 13 jours), mise en commun (garde de rôle, table de routes) M. **Total : environ 18 jours.** Les 42 `auto` ne coûtent rien ; leur reliquat (177, 185) est S.

Écarts constatés entre le cahier et le code ou entre le cahier et lui-même (à corriger dans le cahier, pas dans le test) :

- L'en-tête de la partie 4 annonce « 440 lignes » (`REC-PAR-001` à `440`) alors que la numérotation va jusqu'à 481.
- `REC-PAR-215` et `216` citent `?semaine=2099-« Mot de passe »` et `1999-« Mot de passe »` : le code attend une semaine ISO `AAAA-Www` (`/^\d{4}-W\d{2}$/` dans `WeeklyReport.tsx`) ; la valeur `W..` a été remplacée par erreur dans le cahier. Les tests utilisent `2099-W01` et `1999-W01`.
- `REC-PAR-165` à `207` : la colonne Cas porte `fixture · cas · auto` (format nouveau) alors que les autres lignes de la tranche portent le cas seul : le script `cahier_check.py` doit accepter les deux (déjà le cas).

## 2. Écrans de la tranche

Chaque test porte une étape `test.step("REC-PAR-nnn · …")` par scénario et démarre par `signInAs(context, "<fixture>")`. Sauf mention, la donnée est lue **côté serveur** (Server Components, `getServerApi()`), donc la fausse API HTTP est obligatoire ; les actions (boutons, formulaires, modales) passent par le **navigateur** (`getBrowserApi()`). Axe à chaque état ; les scénarios « 360 px » tournent sur le projet `mobile`.

## 6. Dépendances et risques

Ordre conseillé :

1. Socle commun : `me.role`, `POST auth/logout/`, `unread`, `Faults.parentReadError/DelayMs`, `famille-parent.ts` (enfants, actions dérivées), table de routes du shell. Débloque shell, accueil, liste, détail.
2. Shell (`001`–`018`), accueil (`019`–`037`), liste (`038`–`050`).
3. Détail et ajout d'enfant (`051`–`092`, `098`), puis modification (`125`–`135`).
4. Consentements (`094`–`124`, hors B/C).
5. Événements (`136`–`164`, `221`–`239`), qui réutilisent `paiement.ts`.
6. Rapport (`208`–`220`), paramètres (`240`–`250`).

Risques techniques :

- **Âge et dates** (`084`, `085`, `127`, `212`–`216`) : la fausse API compare à `Date.now()` ; les tests calculent leurs dates à partir d'aujourd'hui et testent la veille et le jour de l'anniversaire. Éviter une horloge figée côté serveur Node (elle n'est pas pilotée par `page.clock`).
- **Pending-actions dérivées** (`028`, `045`, `097`) : sans état partagé, l'accueil afficherait toujours les mêmes lignes ; c'est le point central de la fausse API famille.
- **Réseau coupé, hors ligne** (`015`, `068`, `090`, `110`, `132`, `237`) : `OfflineGate` dépend des événements `online/offline` ; vérifier avec `context.setOffline`.
- **Attente de confirmation de paiement** (`144`, `228`) : horloge de Playwright (`page.clock`), comme dans `parent-demande-paiement.fixtures.spec.ts`.
- **Lien SMS à usage unique et SMS réels** (`093`) : uniquement sur vraie stack avec Mailpit.
- **Doublons** : `REC-PAR-002` recoupe `REC-PAR-324` ; `REC-PAR-229` recoupe la fiche « paiement tardif » existante : une seule aide partagée.
- **Reliquats `auto, partiel`** : `177` (isolation de la liste) et `185` (Kit Code saisi) sont à compléter, effort S chacun.
