# Plan de tests · pages publiques, REC-PUB-001 à REC-PUB-210

Statut : proposition à valider par le produit. Aucune ligne de code de test n'est écrite par ce document. Il suit la stratégie de [PLAN-DE-TESTS.md](../PLAN-DE-TESTS.md) et le dispositif de [FIXTURES-FAUSSE-API.md](../FIXTURES-FAUSSE-API.md).

## 1. En-tête

- **Tranche** : partie 1 du cahier, `REC-PUB-001` à `REC-PUB-210` (de « PublicShell » à la fiche événement, hors chargement et erreur de la fiche événement, REC-PUB-211 et 212, qui ouvrent la tranche suivante).

## 2. Écrans de la tranche

Légende des colonnes. **Stratégie** : A, B, C, D ou E (voir l'en-tête). **Fixture ou condition** : le nom d'un univers de fausse API (section 3) suivi du projet Playwright : « bureau » (1280 px), « mobile » (360 px), rien = les deux projets. « Session `x` » : scénario de session existant, posé par `signInAs` (cookie lu par les appels du navigateur). Tout test d'axe passe par `expectAccessible` (`apps/web/e2e/support/a11y.ts`), qui contrôle aussi l'absence de défilement horizontal.

Convention d'un test : une étape `await test.step("REC-PUB-nnn · <action du cahier>", …)` par scénario (contrôlée par `python3 scripts/cahier_check.py`) ; quand le texte du cahier change, l'étape suit.

## 4. Fausse API à étendre

### 4.1 Contrainte structurante : le cache des pages publiques

`apps/web/src/app/(public)/layout.tsx` l'écrit : les pages publiques « sont prérendues et mises en cache ». Concrètement, `lib/catalog.ts`, `lib/events.ts` et `lib/shop.ts` déclarent `"use cache"` avec `cacheLife("minutes")` et appellent l'API par `getPublicApi()`, un client **anonyme** qui n'envoie ni cookie ni en-tête. Deux conséquences :

1. Le mécanisme actuel (« le scénario voyage dans le cookie `sessionid` ») **ne s'applique pas** : pour la fausse API, le rendu serveur d'une page publique arrive sans session. C'est pourquoi `ecrans/boutique.ts` répond aujourd'hui la même chose à tous les scénarios pour le catalogue.
2. Le cache est propre au processus Next et vit de 1 à 60 minutes (`minutes` : revalidation après 1 minute, expiration après 1 heure) ; la clé est faite des arguments (`category`, `page`, `slug`). Deux tests qui regardent la même liste dans le même processus partagent donc la réponse déjà mise en cache : un état « erreur » ou « chargement » ne peut être observé que pour une clé encore jamais lue avec succès. Les erreurs, elles, ne sont pas mises en cache.

Décision proposée : **un processus `next start` par univers**, tous branchés sur **une seule** fausse API qui distingue l'univers par un préfixe d'URL.

- `apps/web/e2e/fausse-api/server.ts` : reconnaître `/__u/<univers>/` en début de chemin, le retirer avant la recherche de route, et mettre `univers` (nom) dans le `Context` (`contexte.ts`). Aucune autre route existante ne change. `openapi-fetch` concatène `baseUrl` et chemin : `API_URL=http://localhost:4010/__u/api-en-panne` donne `/__u/api-en-panne/api/catalog/categories/`. Le navigateur reçoit la même base par `PUBLIC_API_URL` (`/runtime-config`) : ses appels (« Ajouter ») portent donc le préfixe et le cookie de session.
- Un scénario de session reste prioritaire pour les appels du navigateur : si le cookie `sessionid` porte un scénario, `GET shop/kits/{slug}/` répond par `kitOf` (existant) ; sinon par l'univers.
- `apps/web/playwright.public.config.ts` (nouveau, copie de `playwright.fixtures.config.ts`) : 1 `webServer` pour la fausse API et 6 pour Next (`next start -p 3101…3106`, `API_URL` et `PUBLIC_API_URL` propres), `testMatch: "public/**/*.fixtures.spec.ts"`, mêmes projets `bureau` et `mobile`. `playwright.fixtures.config.ts` reçoit `testIgnore: "public/**"` pour ne pas jouer ces fichiers contre l'univers par défaut.
- `apps/web/e2e/support/univers.ts` (nouveau) : `UNIVERS` (nom → `baseURL`), `armer`, `liberer`, `basculer(univers, "panne" | "ok")`, et un `test.use({ baseURL })` par fichier.
- Coût : 6 processus Next et un build commun (`pnpm build` déjà exigé). Si la mémoire de la CI manque, fusionner `catalogue-vide` et `catalogue-pagine` en un univers où ces états sont choisis par un slug de catégorie réservé, au prix d'une altération des filtres de REC-PUB-082 (déconseillé).

Alternative écartée : ajouter dans le code de production une variable d'environnement qui désactive le cache en test. Elle mettrait du code de test dans l'image et ne dirait rien de ce que l'utilisateur voit en production (où le cache existe).
